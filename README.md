# Sugarcoated?

A rule-based food-label risk analyzer for Indian packaged foods. Search a product or paste an ingredient list, and get a personalized health score, nutrient insights against real public health guidelines, and diet-profile suitability — all explainable, all offline, no ML black box.

Built for Reverie Hacks 2026, Software Development track.

## Why this exists

Indian packaged food labels are dense and hard to parse quickly. "Refined palm oil," "invert sugar syrup," "hydrolyzed vegetable protein" — most shoppers don't have time to look each one up, compare it to a daily limit, or figure out if a product fits their diet. Sugarcoated does that translation instantly, and shows its work at every step so nothing is a black box.

## What it does

- **Healthscore (/10):** flags risky ingredients (added sugars, trans fats, preservatives, allergens) against a curated severity table, and scores the product
- **Macros:** shows each nutrient as a percentage of your personal daily limit (BMR-adjusted if you provide your stats, or standard population guidelines otherwise), plus a protein-per-fat efficiency comparison against similar products
- **Dietician:** checks the product against a diet profile (vegan, diabetic-friendly, low-sodium, gluten-free) and explains exactly why it passes or fails
- **Alternates:** for every tab, suggests same-category products that score better, are more nutrient-efficient, or actually pass your diet profile
- **Fuzzy matching:** typos in pasted ingredients (e.g. "PLOtein") are still matched, and the match is shown transparently so nothing is silently guessed

## Two ways to analyze a product

1. **Search mode** — fuzzy-searches 852 pre-loaded Indian packaged products by name/brand
2. **Paste mode** — paste any raw ingredient list, pick the closest category, optionally add nutrition numbers for a fuller Macros tab

## Architecture

Two-stage design: an offline data pipeline that runs once, and a lightweight runtime app that only ever reads pre-computed data plus does live matching on user input.

```
data/
  packaged_foods_india.csv   Source dataset — 852 Indian packaged products, ingredients + nutrients
  redflag_ingredients.csv    Curated severity table — ~52 ingredients tagged by category and risk level
  products.json              Pre-scored output, regenerated by build_dataset.py

build_dataset.py             Offline pipeline: normalize → match → score → export products.json
matching.py                  Shared ingredient matching (exact + fuzzy) — used by both the pipeline and the live app
scoring.py                   Severity scoring, /10 normalization, risk bucket assignment
macro_insights.py            BMR-based personal targets, % of daily limit, nutrient efficiency ratio
diet_profiles.py             Vegan / diabetic-friendly / low-sodium / gluten-free checks
alternates.py                One generic same-category filter+sort function, reused by all three tabs
app.py                       Streamlit app: intake form, search/paste input, three tabs
```

There is no live external API call at runtime and no ML model in the core scope — every score is traceable back to a specific rule in `redflag_ingredients.csv` or a specific published health guideline.

## How to run it

```bash
pip install -r requirements.txt
python build_dataset.py       # only needed if you've edited the CSVs — regenerates products.json
streamlit run app.py
```

Opens at `http://localhost:8501`.

## Scoring methodology

- Every flagged ingredient carries a severity: high (5 points), medium (3), low (1)
- Points are summed and normalized to a healthscore out of 10 (10 = cleanest)
- Internally also bucketed as Low (0-4 points) / Moderate (5-9) / High (10+) for category-level comparisons

## Nutrient limit sources

- Sugar: WHO / ICMR free sugar guidance (25g/day)
- Sodium: ICMR-NIN daily sodium guidance (2000mg/day)
- Saturated fat: standard 10%-of-2000kcal-diet guidance (~22g/day)
- Trans fat: flagged directly if present at all — FSSAI caps trans fat at 2% of total fat, and health guidance is to minimize it entirely rather than treat it as a percentage budget

These are population-level public health guidelines applied per serving, not personalized medical thresholds, and this tool is not medical advice.

## Honest scope and limitations

- **No OpenFoodFacts live integration** — the catalog is a static local dataset of 852 Indian products, not a live lookup
- **No OCR** — ingredient input is text only (search or paste), not photo scanning
- **Fuzzy matching is heuristic** — a similarity threshold, not a perfect speller; very unusual typos may still be missed
- **BMR formula (Mifflin-St Jeor) is a standard estimate**, not a clinical calculation, and intake is entirely optional
- **Alternates depend on catalog coverage** — a very niche custom category may have no comparable products in the 852-item dataset, and the app says so explicitly rather than showing nothing unexplained
